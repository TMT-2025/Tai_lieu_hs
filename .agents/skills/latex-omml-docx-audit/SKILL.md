# LaTeX OMML DOCX Audit

## Core purpose

Use this skill only for diagnosis. It does not create the final Word document. It answers questions like:

- Does this DOCX contain native Word formulas?
- Are formulas stored as OMML or as plain text?
- Why did this document fail while another one succeeded?
- Is the file likely generated by `python-docx` plus raw LaTeX text?

## Default workflow

1. Run `scripts/audit_docx_formula_state.py` on the target `.docx`.
2. Run `scripts/audit_docx_word_style.py` when the user also cares about typography or template compliance.
3. If the user wants a safe template-level fix, run `scripts/fix_docx_word_style.py` to rewrite body and heading style defaults.
4. If the user provides multiple files, audit each one and compare:
   - OMML node counts
   - raw LaTeX residue counts
   - text-run evidence in `word/*.xml`
   - font, color, and italic compliance
5. Classify the result:
   - `native-omml`
   - `mixed-state`
   - `plain-text-latex`
   - `no-formula-evidence`
6. Explain the likely root cause in plain language.
7. If the user wants remediation, route to `$markdown-to-word-omml`, `$formula-docx-native`, or apply the style fixer when the issue is only template styling.
8. If the user also cares about typography, note whether the file follows SimSun for Chinese, Times New Roman for English, HeiTi for headings, black text, and non-italic titles.

## Interpretation rules

- Non-zero `<m:oMath>` or `<m:oMathPara>` means the DOCX contains native Word math.
- High raw LaTeX residue in `w:t` nodes means formulas were likely written as plain text.
- `Cambria Math` font usage without OMML is not success.
- A document can be in `mixed-state` if it contains some OMML but also retains raw LaTeX text in normal Word runs.

## Recommended command

```bash
python scripts/audit_docx_formula_state.py file.docx
python scripts/audit_docx_word_style.py file.docx
python scripts/fix_docx_word_style.py file.docx --output fixed.docx
```

JSON mode for automation:

```bash
python scripts/audit_docx_formula_state.py file.docx --json
```

## What to report

When summarizing results, include:

- OMML node count
- block formula node count
- raw LaTeX residue count
- style compliance summary
- diagnosis label
- likely failure reason
- suggested fix path
- whether a style-only repair is sufficient

## Failure patterns to recognize

- `python-docx add_run()` inserted LaTeX into `w:t`
- conversion pipeline changed font only
- Pandoc or OMML conversion step was skipped
- formula delimiters were stripped before export
- document is only partially converted
